# Восстановление медиа Яндекс Диска

## Цель

Приложение восстанавливает локальную коллекцию после повреждения серверов Яндекс Диска. Оно рекурсивно обходит выбранную исходную папку и создаёт в выбранной папке восстановления безопасную копию структуры каталогов:

* Полный файл фото или видео копируется только если он действительно открывается/декодируется.
* Если полного файла нет или он повреждён, приложение сначала пытается получить большое локальное превью Windows Explorer и сохраняет PNG с префиксом `PREW_`; затем получает самое большое серверное превью через авторизованный Chrome как `WEBPV_`; последним вариантом сохраняет маленькую обложку Explorer как `MINIPV_`.
* Уже существующий путь в папке восстановления имеет абсолютный приоритет: его не менять и не перезаписывать.

## Разработка

* Java 21, Gradle, Swing. Основные границы: UI, конфигурация, планирование, проверка медиа, получение превью и файловые операции.
* Не определять статус по цвету оверлея Яндекс Диска: Explorer не предоставляет его как стабильный файловый атрибут. Перед декодированием учитывать Windows-флаг `dos:offline`, чтобы не гидратировать облачную заглушку; надёжный критерий полного файла — успешное декодирование. Браузерный канал строит URL из пути, относительного к выбранному корню Диска, и открывает режим просмотра файла; Windows Shell применяется только как резервный источник.
* Перед изменением бизнес-логики написать или обновить JUnit-тесты. Проверять как минимум: приоритет папки назначения, сохранение относительного пути, классификацию читаемого/нечитаемого файла и идемпотентность повторного запуска.
* Не удалять и не перезаписывать данные источника или назначения. Любая ошибка одного файла записывается в итог и не прерывает весь обход.
* Папки сохранять сразу после подтверждения выбора в `yandex-media-recovery.properties` рядом с программой. Для каждого запуска создавать рядом с программой CSV-лог с датой и временем в имени; строку для каждого изменённого файла сразу сбрасывать на диск. Допустимые статусы CSV: `SRC_SAVED`, `WEBPV_SAVED`, `PREW_SAVED`, `MINIPV_SAVED`, `PREVIEWS_CLEANED`, `NO_FILE`; неизменённые файлы не логировать.
* Приоритет результатов: оригинал, `WEBPV_`, `PREW_`, `MINIPV_`. При включённой по умолчанию настройке удалять только менее качественные превью в папке назначения; оригиналы в папке назначения никогда не заменять. Перезапись допускается только для файлов превью при явно включённой настройке. Параллельную обработку ограничивать выбором пользователя от 1 до 10 потоков и сохранять этот выбор.
* Кнопка входа открывает Chrome с отдельным постоянным профилем приложения. Не читать и не записывать пароль, cookie или OAuth-токены. Обращения к Яндекс Диску выполнять через один синхронный канал с интервалом не менее двух секунд между открытиями файлов, независимо от числа потоков восстановления.
* Публичные классы и нетривиальные методы документировать Javadoc. Предпочитать стандартную библиотеку и зрелые зависимости самописным парсерам.
* Перед сдачей выполнять `gradle test` и `gradle build`.

## Ограничение

Превью можно восстановить только когда Яндекс Диск в авторизованном веб-клиенте возвращает серверное превью либо Windows Shell/кэш Explorer возвращает реальную миниатюру. Без них и без полного файла восстановить изображение невозможно.
