# Восстановление медиа Яндекс Диска

## Цель

Приложение восстанавливает локальную коллекцию после повреждения серверов Яндекс Диска. Оно рекурсивно обходит выбранную исходную папку и создаёт в выбранной папке восстановления безопасную копию структуры каталогов:

* Локально доступный оригинал любого типа копируется в папку восстановления. Нельзя открывать или копировать облачную заглушку, если Windows пометила её `OFFLINE` или `RECALL_ON_DATA_ACCESS`: это может инициировать скачивание и зависнуть.
* Для фотографии без доступного оригинала приложение сначала пытается получить большое локальное превью Windows Explorer и сохраняет PNG с префиксом `PREW_`; затем получает самое большое серверное превью через авторизованный Chrome как `WEBPV_`; последним вариантом сохраняет маленькую обложку Explorer как `MINIPV_`.
* Недоступный на диске файл, который не является фотографией, не имеет пути восстановления: он получает статус `NO_FILE`.
* Уже существующий путь в папке восстановления имеет абсолютный приоритет: его не менять и не перезаписывать.

### Последовательность по состоянию файла

| Состояние | Фото | Остальные файлы |
| --- | --- | --- |
| Файл уже есть в папке восстановления | Ничего не менять; `ALREADY_OK` (не логировать). | Ничего не менять; `ALREADY_OK` (не логировать). |
| Файл доступен в папке источнике, но нет в папке назначения | Скопировать оригинал; `SRC_SAVED`. Превью не получать. | Скопировать оригинал независимо от расширения; `SRC_SAVED`. |
| Файла нет, доступно большое превью в Windows | Сохранить большое превью как `PREW_…png`; `PREW_SAVED`. Браузер и минипревью не использовать. | Не открывать файл и не получать превью; `NO_FILE`. |
| Файла нет, доступно большое превью в браузере | Только если большое превью Windows не дало пригодный результат: сохранить серверное превью как `WEBPV_…`; `WEBPV_SAVED`. Минипревью не использовать. | Не открывать файл и не получать превью; `NO_FILE`. |
| Файла нет, доступно маленькое превью | Только если большое превью Windows и браузера не дали пригодный результат: сохранить как `MINIPV_…png`; `MINIPV_SAVED`. | Не открывать файл и не получать превью; `NO_FILE`. |

## Разработка

* Java 21, Gradle, Swing. Основные границы: UI, конфигурация, планирование, проверка медиа, получение превью и файловые операции.
* Главное окно содержит ленивое дерево подпапок выбранного корня Яндекс Диска с флажками. По умолчанию выбраны все ветки; пользователь может исключать и повторно включать вложенные ветки. Отбор выполняется до планирования, поэтому исключённые поддеревья не обходятся. Папку `.sync` не показывать и не обрабатывать; относительные пути всегда считать от корня Диска.
* Не определять статус по цвету оверлея Яндекс Диска: Explorer не предоставляет его как стабильный файловый атрибут. Перед декодированием учитывать Windows-флаг `dos:offline`, чтобы не гидратировать облачную заглушку; надёжный критерий полного файла — успешное декодирование. Браузерный канал строит URL из пути, относительного к выбранному корню Диска, и открывает режим просмотра файла; Windows Shell применяется только как резервный источник.
* Перед изменением бизнес-логики написать или обновить JUnit-тесты. Проверять как минимум: приоритет папки назначения, сохранение относительного пути, классификацию читаемого/нечитаемого файла и идемпотентность повторного запуска.
* Не удалять и не перезаписывать данные источника или назначения. Любая ошибка одного файла записывается в итог и не прерывает весь обход.
* Папки и выбранные ветки дерева сохранять сразу после изменения в UTF-8 YAML-файл `yandex-media-recovery.yaml` рядом с программой. Для каждого запуска создавать рядом с программой CSV-лог с датой и временем в имени; строку для каждого изменённого файла сразу сбрасывать на диск. Допустимые статусы CSV: `SRC_SAVED`, `WEBPV_SAVED`, `PREW_SAVED`, `MINIPV_SAVED`, `PREVIEWS_CLEANED`, `NO_FILE`; неизменённые файлы не логировать.
* Приоритет результатов: оригинал, `WEBPV_`, `PREW_`, `MINIPV_`. При включённой по умолчанию настройке удалять только менее качественные превью в папке назначения; оригиналы в папке назначения никогда не заменять. Перезапись допускается только для файлов превью при явно включённой настройке. Один основной поток последовательно обходит папки; для каждой текущей папки её файлы распределяются между 1–10 рабочими потоками, и следующая папка не начинает обработку до завершения текущей.
* Кнопка входа открывает Chrome с отдельным постоянным профилем приложения. Не читать и не записывать пароль, cookie или OAuth-токены. Обращения к Яндекс Диску выполнять через один синхронный канал с интервалом не менее двух секунд между открытиями файлов, независимо от числа потоков восстановления. Следующий файл открывать только после декодирования большого превью текущего файла в браузере либо после его контролируемого таймаута.
* Отладка браузера сохраняется в properties, принудительно использует один поток и делает Chrome видимым на странице текущего файла. Кнопка остановки отменяет рабочие задачи, закрывает управляемый Chrome и не удаляет никакие исходные или целевые данные.
* Публичные классы и нетривиальные методы документировать Javadoc. Предпочитать стандартную библиотеку и зрелые зависимости самописным парсерам.
* Новые созданные файлы сразу добавлять в Git командой `git add <путь-к-файлу>` до дальнейших изменений.
* Для компактной Windows-поставки использовать исходный файл `installer/download-dependencies.bat`: по явному действию пользователя он восстанавливает Java Runtime и Maven-библиотеки рядом с EXE. В поставку не включать и не скачивать профиль сессии, cookie, пароли или Chrome.
* Перед сдачей выполнять `gradle test` и `gradle build`.

## Ограничение

Превью можно восстановить только когда Яндекс Диск в авторизованном веб-клиенте возвращает серверное превью либо Windows Shell/кэш Explorer возвращает реальную миниатюру. Без них и без полного файла восстановить изображение невозможно.
