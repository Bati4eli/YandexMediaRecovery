# Восстановление медиатеки Яндекс Диска

Десктопное Java-приложение для бережного восстановления локальной медиатеки, когда часть файлов Яндекс Диска осталась только как облачные заглушки, но их миниатюры видны в Проводнике.

## Запуск

Требуется JDK 21 или новее.

```powershell
.\gradlew.bat run
```

Первое окно содержит только корень локального Диска `%USERPROFILE%\Yandex.Disk` и корень резервной копии `D:\YandexDisk-BACKUP`. Их можно изменить кнопками выбора. Каждый подтверждённый выбор сразу сохраняется рядом с программой в `yandex-media-recovery.properties`.

## Что делает программа

1. Рекурсивно обходит исходную папку.
2. Открывает каждый поддерживаемый файл. Декодируемые фото и видео копирует в ту же относительную папку назначения.
3. Для недоступного или повреждённого медиа сначала обращается к авторизованному веб-клиенту Яндекс Диска. Он открывает режим просмотра файла и получает самое большое доступное серверное превью; для проверенного файла `PICT0641.JPG` это 1280×960 px. Затем, если браузерное превью недоступно, запрашивается миниатюра Windows Shell — сначала до 2048 px, затем до 512 px. Сохранённый PNG получает имя `PREW_<исходное-имя-без-расширения>.png`.
4. Не заменяет оригинал в целевой папке. Существующее `PREW_`-превью также пропускается, если не включена настройка «Перезаписывать превью PREW_».

Нажмите «Войти в Яндекс Диск…», чтобы приложение открыло Chrome с отдельным постоянным профилем. Вход выполняется пользователем вручную; пароль, cookie и OAuth-токены не попадают в настройки или журналы. Когда после входа откроется корень Диска, видимое окно Chrome автоматически закроется, а сессия сохранится для фонового восстановления. Браузерный канал намеренно последовательный и делает не более одного нового запроса раз в две секунды, даже если локальная обработка использует 1–10 потоков. В окне можно включить перезапись только `PREW_`-превью и выбрать от 1 до 10 потоков обработки; оба параметра сохраняются. Панель прогресса показывает номер текущего файла, а крупный журнал выводит одну строку с эмодзи и относительным путём для каждого завершённого файла. Ошибки отдельных файлов не прерывают остальную операцию.

Для каждого запуска рядом с программой создаётся файл `recovery-log-ГГГГ-ММ-ДД_чч-мм-сс.csv`. В нём после обработки каждого файла сразу сохраняется строка `path,file_name,status`. Статусы: `SRC_SAVED`, `PREVIEW_SAVED`, `NO_FILE`, `ALREADY_OK`.

## Ограничения

Цвет оверлея Яндекс Диска (зелёная галочка/синие стрелки) не доступен Java как надёжное файловое свойство. Перед проверкой содержимого программа использует стандартный Windows-флаг `dos:offline`, чтобы не открывать и не гидратировать облачную заглушку; полный файл всё равно копируется только после реального декодирования. Браузерный вариант требует установленный Chrome и выполненный в отдельном окне вход в Яндекс. Если серверное превью и Shell-кэш недоступны, изображение восстановить технически невозможно.

## Проверка

```powershell
.\gradlew.bat test build
```

Тесты проверяют декодирование, сохранение относительных путей, приоритет уже существующих файлов и запись PNG-превью.
